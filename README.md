# DeproLLM

DeproLLM — индивидуальный исследовательский проект, выполняемый в рамках
проектной практики ИТМО по задаче
[Пситехлаба](https://psytechlab.github.io/). Его цель — проверить, можно ли
научить небольшую языковую модель генерировать русскоязычные эссе со
стилистическими особенностями текстов людей с депрессией.

В работе используется `Qwen3-4B-Instruct-2507`. Модель дообучается методом
GRPO по сигналу классификатора психолингвистических и грамматических признаков.
Текущий этап ограничен эссе — типом текстов, для которого доступен подходящий
классификатор и воспроизводимый сигнал обучения.

Исходная задача связана с дефицитом данных. В исследовании
[Stankevich et al.](https://repository.rudn.ru/ru/records/article/record/65816/)
было собрано 316 русскоязычных эссе, в том числе 93 текста людей с клинически
подтверждённой депрессией. Такой корпус позволяет построить классификатор, но
ограничивает обучение более требовательных к объёму данных моделей. Полученный
генератор рассматривается как возможный способ создавать дополнительные
контролируемые тексты без прямого копирования исходного корпуса.

## Почему важна стилистика

Простая инструкция «пиши как человек с депрессией» часто приводит к прямым
упоминаниям депрессии, симптомов и негативных переживаний. Такой текст может
получить высокий score благодаря содержанию, а не особенностям письма.

Цель DeproLLM — управлять более общими свойствами текста: грамматическими
конструкциями, психолингвистическими показателями и структурой изложения. Для
этого reward учитывает 73 признака классификатора и штрафует частое
использование прямой негативной лексики.

## Схема обучения

```text
нейтральная тема -> Qwen3-4B + LoRA -> эссе
                         ^              |
                         |              v
                       GRPO <- reward <- классификатор
```

Классификатор имеет структуру
`StandardScaler -> PCA(46) -> RBF SVC`. Его параметры и порядок 73 входных
признаков во время обучения не изменяются. Raw score преобразуется сигмоидой,
откалиброванной по baseline-текстам, и объединяется с контролем длины,
полноты, качества и нежелательной лексики. После обучения для обычной
генерации нужны только Qwen3-4B и полученная LoRA.

## GRPO улучшает небольшую модель

Проведены два независимых 300-шаговых запуска с одинаковыми параметрами и
разными training seed. В обоих случаях эффект переносился на темы, не
использованные при обучении.

В итоговом контролируемом сравнении исходная Qwen получила подробный промпт с
описанием требуемого стиля, а GRPO-модели писали в том же личном формате без
дополнительной стилевой инструкции. `decision_function` — знаковый score SVC,
в котором ноль разделяет классы, а не вероятность. В этой задаче модели нужно
сдвинуть нелинейное сочетание 73 признаков, сохранив тему и не прибегая к
прямой депрессивной лексике.

GRPO повысил средний score с `−0.654` до `−0.278` и `−0.152`, а число текстов
по положительную сторону SVC — с 2 из 60 до 18 и 23 из 60. Таким образом,
единичные срабатывания исходной модели превратились в регулярную генерацию
текстов с целевым сочетанием признаков. Эффект был положительным для 17 из 20
тем в обоих запусках, а лексический штраф по-прежнему сработал только для
одного текста из 60. Отрицательный средний score означает, что результат ещё
не одинаков для всех генераций, но не отменяет достигнутого сдвига
распределения и роста доли целевых текстов.

## Почему не ограничиться промптингом

Промптинг действительно способен повысить score. Однако у исходной Qwen
простая ролевая инструкция привела к лексическому штрафу в 54 из 60 текстов:
модель в основном использовала прямую депрессивную семантику.

Более строгий промпт без таких упоминаний был проверен как на исходной Qwen,
так и на более сильной внешней модели `GLM-5.3-Flash`.

| Модель и условие | Средний score | Лексический штраф |
| --- | ---: | ---: |
| Qwen3-4B, constrained-промпт | −0.654 | 1/60 |
| Qwen3-4B + GRPO, два запуска | −0.278 / −0.152 | 1/60 в каждом |
| GLM-5.3-Flash, constrained-промпт | −0.271 | 7/60 |

По среднему score первая GRPO-модель оказалась примерно на уровне
`GLM-5.3-Flash`, а вторая — выше неё. Это межмодельное сравнение является
дополнительным: наиболее строгий вывод даёт сопоставление исходной и
дообученной Qwen в одном генерационном pipeline.

Сильная модель с промптом не требует отдельного обучения и удобна для редких
запросов. Небольшую специализированную модель можно запускать в собственной
инфраструктуре, не передавать тексты внешнему сервису и потенциально дешевле
использовать регулярно. Reward также позволяет объединять несколько
автоматически проверяемых требований, которые трудно стабильно задать одной
инструкцией. Стоимость и скорость вариантов в этой работе напрямую не
измерялись.

## Возможное развитие

Уже в текущем виде две LoRA заметно повышают долю текстов с целевым сочетанием
признаков и могут служить управляемым источником кандидатов для следующих
экспериментов. В перспективе такую генерацию можно использовать для создания
синтетических данных и обучения других моделей, например классификаторов
сообщений из социальных сетей. Для перехода к этому сценарию ещё предстоит
проверить перенос на новые жанры и независимо оценить качество полученного
стиля. Текущие эксперименты подтверждают сдвиг относительно используемого
классификатора, который одновременно служит частью reward и основной метрикой.

## Состав репозитория

- `grpo_depression.ipynb` — актуальный полный Kaggle workflow: baseline,
  калибровка reward, GRPO, оценка и сохранение результатов;
- `depression_reward/` — reward, извлечение признаков, классификатор и
  локальная проверка;
- `experiments/` — дизайн экспериментов, результаты и код воспроизведения;
- `make_kaggle_runtime.py` — сборка и проверка закрытого reward runtime;
- `check_grpo_notebook.py` — проверка notebook перед запуском;
- `make_grpo_report.py` — сводка артефактов завершённого обучения.

Для первого знакомства достаточно этого README и
[обзора экспериментов](experiments/README.md). Затем можно открыть `DESIGN.md`
и `RESULTS.md` интересующего эксперимента. README и Python-скрипты внутри его
каталога относятся к техническому воспроизведению.

## Воспроизводимость и доступ

Полные промпты, темы, seeds и параметры закреплены в `protocol.json` или
JSON-конфигурациях экспериментов. Notebook соответствует первому полному
запуску с training seed 3407. Второй запуск отличался seed 4407 и
идентификаторами и описан в
`experiments/grpo_training_v1/configs/runs.json`.

Классификатор TITANIS, его словари и параметры были предоставлены для
закрытого использования. Полное воспроизведение обучения и пересчёт scores
требуют доступа к этому runtime. Две обученные LoRA, checkpoints, полные
Kaggle outputs и корпуса генераций хранятся отдельно от Git.

Основные проверки notebook и reward:

```bash
PROTOCOL_BUFFERS_PYTHON_IMPLEMENTATION=python \
  .venv/bin/python -m depression_reward.selfcheck
python3 check_grpo_notebook.py
```

Команды для отдельных экспериментов приведены в их технических README.
